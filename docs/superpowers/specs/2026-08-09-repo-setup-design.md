# RSNA Knee Abnormality Detection — Repo Setup Design

Date: 2026-08-09
Status: Approved

## Problem

The repo (`kaggle-rsna-knee-abnormality-detection`) is a fresh, empty git
checkout (no commits) for the Kaggle competition
[rsna-knee-abnormality-detection](https://www.kaggle.com/competitions/rsna-knee-abnormality-detection).
It needs to be scaffolded to match the conventions of the other repos under
`~/Documents/GitHub/2. Kaggle/`, tailored for this competition's specifics:
a 569.76 GB dataset of DICOM knee MRI series paired with free-text radiology
reports, a 12-label multi-label classification task (macro-averaged AUC-ROC),
a Code Competition (submissions must come from a Kaggle Notebook rerun,
internet disabled, ≤9h CPU/GPU), and a separate Efficiency Track.

## Competition summary (source of truth: user-provided overview/data
description, 2026-08-09)

- **Task**: predict per-study probability for 12 findings — ACL, MCL, Medial
  Meniscus, Lateral Meniscus, Medial OA, Lateral OA, PF OA, Effusion,
  Synovitis, Baker's, Contusion, Fracture.
- **Metric**: macro-averaged AUC-ROC across the 12 targets.
- **Data**:
  - `train.csv` — one row per study: `StudyInstanceUID`, `PatientSex`,
    `Report` (free text, multilingual), 12 binary labels. Only a small
    subset of training studies carry labels; the rest have only the report
    text, which may be used to derive weak labels.
  - `train_series.csv` — one row per series: `StudyInstanceUID`,
    `SeriesInstanceUID`, `Fluid_Sensitive`, `Fat_Suppression`,
    `Anatomical_Plane` (Sagittal/Coronal/Axial).
  - `train_series/<StudyInstanceUID>/<SeriesInstanceUID>/<SOPInstanceUID>.dcm`
    — per-slice DICOM, 20–45 slices/series typically (median 30), long tail
    to a few hundred. Mixed transfer syntaxes (uncompressed Explicit VR LE,
    JPEG Lossless, JPEG 2000, Implicit VR LE). Stripped to 86 allowlisted
    metadata tags.
  - `test.csv` / `test_series.csv` / `test_series/` — same schema, ~1300
    studies at real scoring time; local copies are just 3 example studies.
  - `sample_submission.csv` — all-0.5 baseline.
- **Timeline**: started 2026-07-30 (per this year's schedule); entry
  deadline / team merger 2026-10-15; final submission 2026-10-22; winners'
  requirements 2026-11-05.
- **Code requirements**: submission via Notebook only, ≤9h runtime,
  internet disabled at scoring time, freely available external
  data/pretrained weights allowed, output must be `submission.csv`.
- **Efficiency Track**: separate prize track scoring both accuracy and
  runtime; relevant to inference-cost decisions later but not to initial
  scaffolding.

## Decisions (confirmed with user)

1. **Kaggle-only execution.** All data access, training, and inference run
   as Kaggle Kernels via the Kaggle CLI (`kaggle kernels push`,
   `kaggle competitions submit`, GPU kernels for training). The 569.76 GB
   dataset is never downloaded locally, and no code is expected to execute
   against real data outside Kaggle. Same constraint `kaggle-biohub-cell-
   tracking-during-development` operates under, at ~6.5x the dataset size.
2. **Tested local `src/` package, not notebook-only.** Reused logic — DICOM
   series/study loading across mixed transfer syntaxes, report-based weak-
   label mining, study-level dataset assembly, the macro-AUC metric — lives
   in `src/knee_mri/`, covered by `tests/` running against small synthetic
   fixtures (synthetic DICOM files written with `pydicom`, synthetic report
   strings), so it's verified without needing real data or a Kaggle
   session. Matches `kaggle-biohub-cell-tracking-during-development` and
   `kaggle-nfl-player-contact-detection`, not the notebook-only
   `kaggle-birdclef-2026` shape.
3. **No official baseline to vendor.** Unlike biohub (which vendors
   `royerlab/kaggle-cell-tracking-competition`), this competition has no
   known official starter repo — `src/knee_mri/` is written from scratch,
   uv/pyproject-managed.
4. **`src/` distributed to Kaggle via a private code-dataset**, matching
   biohub's `publish_code_dataset.sh` pattern: staged in a clean temp
   directory (not `kaggle datasets create -p .` from repo root, which
   biohub found does not honor `.kaggleignore` for directory uploads),
   published as a private Kaggle Dataset, and attached to kernels via
   `dataset_sources` in each `kernel-metadata.json`.
5. **Package name**: `knee_mri`.

## `01_eda.ipynb` stub content

- Purpose statement (short paragraph).
- Config cell: `IS_KAGGLE` autodetection resolving
  `/kaggle/input/competitions/rsna-knee-abnormality-detection/`, deterministic
  seed, `NOTEBOOK_VERSION` string.
- Real (not placeholder) analysis cells, committed output-free until run on
  Kaggle:
  - Load `train.csv` / `train_series.csv`; label prevalence across the 12
    targets; count of studies with vs. without labels (weak-label
    candidates).
  - Series-per-study distribution; `Anatomical_Plane` /
    `Fluid_Sensitive` / `Fat_Suppression` distributions.
  - `PatientSex` distribution; report language spot-check (the `Report`
    field is multilingual).
  - Slice-count-per-series distribution (median ~30 per the data
    description, to be confirmed against the real mount).
- Markdown insight cell after each result, per the coding-standards
  notebook style — left as placeholders noting "insight pending first
  Kaggle run" rather than fabricated numbers.

## `src/knee_mri` package contents (initial)

- `dicom_io.py`: open a series directory, decode slices across the four
  documented transfer syntaxes, return a stacked volume + spacing/plane
  metadata.
- `labels.py`: weak-label mining scaffolding from `Report` text — initial
  version can be a rule/keyword-based extractor per target label, tested
  against synthetic report strings; real calibration deferred to
  `docs/3_strategy.md` once real report text is inspected.
- `dataset.py`: given `train.csv` + `train_series.csv`, assemble
  study-level records (which series to use per study, given the plane/
  sequence metadata).
- `metrics.py`: macro-averaged AUC-ROC over the 12 label columns, matching
  the competition's evaluation section exactly (`sklearn.metrics.roc_auc_score`
  per column, averaged) — this is the actual leaderboard metric, so it must
  be correct and unit-tested before it's trusted for local validation.

## Testing

- `pytest` + `ruff` via `uv`, same as biohub. `tests/` uses `pydicom` to
  write small synthetic multi-slice series (a few slices, tiny arrays) and
  synthetic report strings/label rows — no real dataset needed, matching
  the Kaggle-only-execution decision above.

## Git hygiene

`.gitignore` excludes: `data/` (not used, but excluded defensively), model
checkpoints/weights, `.venv/`, Python/pytest/ruff caches, notebook
checkpoints, `notebooks/kernels/*/*.ipynb` (regenerated by
`push_kaggle_kernel.sh`), `kaggle.json`/credentials, generated
`submission.csv`.

## Out of scope for this setup pass

- Actually running the EDA notebook on Kaggle (requires pushing to Kaggle
  and a completed kernel run — a follow-up action, not part of scaffolding).
- Real weak-label calibration from report text (needs real report samples
  from a Kaggle run first).
- Baseline model notebook / training — a separate, later piece of work
  once EDA insights exist.
- Accepting competition rules / Kaggle account setup — `~/.kaggle/kaggle.json`
  already exists locally (username `tuannm3812`), reused as-is.
